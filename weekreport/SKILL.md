# 周报（weekreport）

把「我干了啥」变成「领导三行内看得到、也信得过」的几百字。

## 一、四条底线

1. **结论先给。** 第一段就写这周最重要的一件事和它的结论。领导只读前三行，后面才是细节。
2. **事实只搬运，不生产。** 数字、日期、人名、系统名、结论必须能在材料里找到。材料里没有的影响面、百分比、协作方，一个都不写。
3. **宁短不缺真。** 材料只够五条就写五条，不靠形容词凑篇幅。交一份 200 字的周报，好过 600 字的空话。
4. **困难照写。** 卡住的事、没做成的事，是周报里信息密度最高的部分。删掉它，周报就只剩邀功。

## 二、先判断材料属于哪一类

| 材料形态 | 处理方式 |
|---|---|
| 几个关键词 / 短句 | 逐条补「做到哪一步」，缺关键信息就问 |
| 聊天记录、会议纪要 | 只抽「我」做的已发生的动作；别人的决定记成背景，不记成我的产出 |
| commit log / issue 列表 | 按模块合并同类提交，一条周报对应一件事，不是一条 commit |
| 已有日报 | 合并同类项、删重复，按项目重排，不按天堆 |
| 一版草稿 | 先按第七节自检挑毛病，再重写；不在原文上打补丁 |

材料少于三条时先问一次（一次问完，不超过三个问题）；问不出来就交短周报 + 待补清单。

## 三、五步走

1. **归位**：把每条材料放进四个桶——做完了 / 在做 / 卡住 / 下周。放不进的先挂着，别硬塞。
2. **定结论**：从「做完了」里挑出最重要的一件，一句话说清「做了什么 + 结论是什么」。挑不出来说明这周确实没有主线，就照实写「本周以 X 为主，没有结论性进展」——不要硬编一个。
3. **补语境**：每条补三件事里能补的那几件——为谁做、做到哪一步、结果是什么。补不出来就留白。
4. **排序**：结论在前，产出次之，技术细节最后。花三天的事和花十分钟的事不该占同样篇幅。
5. **写**：长短不齐地写。重要的事两句话，小事一句话，一句话能说完的就一句话。

## 四、结构层：让产出可见

这一节是「周报」和「工作日志」的区别。日志记过程，周报要让人看见结果。

| # | 做法 | 反例 → 正例 |
|---|---|---|
| 1 | **产出必须具名** | 「整理了一个调研文档」→「《XX 学习文档》一份，结论：设备不支持，不采用」 |
| 2 | **放弃写成决策** | 「设备不支持，所以放弃了」→「排除 XX：需要专用硬件，现有板卡没有。替代方向是 A 和 B」 |
| 3 | **旧目标必须闭环** | 上上周说「月底投会议」，这周只字不提 → 投没投、中没中、改投哪里，一句话交代 |
| 4 | **下周可验收** | 「继续推进优化函数」→「目标函数 v1：9 个变量的量纲、取值范围、相互约束」 |
| 5 | **卡点写清卡在谁** | 「正积极沟通协调」→「卡在对方测试账号没给，催了两次」 |
| 6 | **累计进度一句话** | 十几周的累计文档里没有一句「现在到哪了」→ 补一句：距下个节点（开题/中期/结题/上线）还差什么 |

技术细节不是不能写，是往后放：**结论 → 产出 → 进展 → 细节**。细节是证据，不是主角。

## 五、语言层：周报特有的 AI 味

通用去 AI 味规则（铺垫、拔高、套话收尾等 31 条）归 `humanizer-zh`，这里只列周报场景独有的：

| # | 毛病 | 长什么样 | 怎么改 |
|---|---|---|---|
| 1 | 三段式拔高 | 「完成了 X，提升了 Y，为 Z 奠定基础」 | 一条事只说一件事。有影响写影响，没影响只写做了什么 |
| 2 | 动词通胀 | 赋能 / 闭环 / 抓手 / 对齐 / 沉淀 / 打通 / 落地 / 助力 | 换成具体动作：改了哪个模块、跟谁确认了什么、发了几版 |
| 3 | 进度模糊 | 稳步推进 / 有序开展 / 持续优化 | 写到哪一步：初版完成 / 等对方反馈 / 卡在权限 |
| 4 | 条条等长 | 五条要点全是 25 字左右、句式一致 | 长短不齐才像人写的。合并次要项，重点项展开 |
| 5 | 无差别加尾巴 | 每件事后面都跟一句「下一步将……」 | 只有真有下一步才写；做完的事不需要尾巴 |
| 6 | 全篇无主语 | 永远是「项目」「团队」在动 | 写「我」。周报是「我这周干了什么」 |
| 7 | 凑整数字 | 提升 30%、覆盖 100%、效率翻倍 | 材料里没有就一个数字都不写 |
| 8 | 开场白收尾 | 「在领导的指导下」「下周我们将继续努力」 | 删。从第一件事开始写，最后一条写完就停 |
| 9 | 装饰性排版 | ✅已完成 🚀进行中 **重点** | 除非公司模板要求，用纯文本条目 |

**原话优先**：材料里已经有的话，能照抄就照抄。把「搞不定」改成「存在一定困难」、把「催了两次」改成「多次跟进沟通」，就是 AI 化的开始——用户自己的用词才是人味的来源。

## 六、扩充的边界

「扩充」只扩表达，不扩事实。同一条材料，可以：

- ✅ **把隐含信息显性化**：材料「修了导出 bug」+「空字段的 csv 会崩」→「修了导出的空指针：带空字段的 CSV 一点导出就崩」
- ✅ **把动作说到具体**：材料提到慢在哪，就写「给订单表的 status 加了索引」；没提就只写「优化了订单查询」
- ❌ 编数字、编影响面（「影响 3000 用户」）、编协作方（「协同三方团队」）、编原因（「由于历史债务」）
- ❌ 把「在做」写成「做完」，把「计划」写成「已经」

材料不够时的优先级：**留占位 > 问 > 编**。占位写成 `〔待补：影响范围〕` 这种一眼看得见的形式，并在文末统一列出。

## 七、输出格式与自检

**标准版**（给领导 / 导师看的周期性汇报）：

```
【第 N 次周报】MM.DD–MM.DD

一句话：本周最重要的一件事 + 结论

一、本周产出
- 《文档 / 程序 / 图 / 数据》名字 —— 一句话价值

二、进展
- 做了什么 → 得到什么 → 所以下一步

三、卡点 / 需要支持
- 卡在谁身上、卡了多久、需要什么

四、下周
- 具体到「什么东西做到什么程度」

五、累计进度
- 项目 / 课题到哪一步，距下个节点还差什么
```

**轻量版**（日报、材料很少、只给自己留痕）：四段就够——本周 / 在做 / 卡住 / 下周。

- 某一节空了整段删掉，不留「无」。
- 用户给了公司模板 → 按模板章节填，不增删标题、不改措辞习惯。
- 用户要一段话（有的公司要叙述体）→ 按「做完的 → 在做的 → 卡住的 → 下周」连成段落。
- 篇幅：标准版 400–800 字，轻量版 5–8 条。
- 有上周周报时，把上周的「下周」逐条对一遍：做了的移进「本周」，没做的进「卡点」并说明原因，或明确说放弃——不要悄悄消失。

**交付前逐项核对**：

- [ ] 第一段能让人知道这周的主线是什么
- [ ] 每项产出都有名字，不是「做了一些工作」
- [ ] 提过的旧目标都有下文，包括没做成的
- [ ] 每条的动词是具体动作，不是「推进 / 落地 / 赋能」
- [ ] 所有数字都能在材料里找到出处
- [ ] 卡点写清了卡在谁身上、卡了多久
- [ ] 下周每条都能验收（什么东西做到什么程度）
- [ ] 出现了「我」或明确的主语
- [ ] 结尾没有套话，最后一条写完就停
- [ ] 占位符都在文末列了一遍

## 八、示例

**材料**（用户原话，四条短句）：

```
导出 bug 修了，空字段的 csv 会崩
产品对需求，批量删除他们还没定
订单接口联调没通，等他们给测试账号，催了两次
监控脚本写完了，每分钟探一次，挂了发企微
```

**不要写成这样**：

> 本周工作稳步推进，主要完成以下内容：
> 1. 完成导出功能缺陷修复，有效提升了系统稳定性，为用户数据导出体验提供了有力保障。
> 2. 与产品团队就下周需求进行了深入对齐，明确了后续工作方向，为项目顺利推进奠定了坚实基础。
> 3. 接口联调工作有序开展中，目前正积极与相关方沟通协调。
> 4. 完成监控脚本编写，进一步提升了系统的可观测性。
> 下周将继续努力，持续推动各项工作落地。

四条材料被写成四条等长的排比句，每条都加了没有信息量的意义；「卡住」被美化成「有序开展中」；主语全程缺席。

**应该写成这样**：

> 本周
> - 修了导出的空指针：带空字段的 CSV 一点导出就崩，现在能正常导。
> - 监控脚本写完，每分钟探一次订单接口，挂了直接发企微。
>
> 在做
> - 跟产品过了下周需求，其中「批量删除」他们还没定要不要做，先挂着。
>
> 卡住
> - 订单接口联调还没通，卡在对方测试账号没给，催了两次。
>
> 下周
> - 账号到位后把联调跑通。

改后没有多出任何一个材料里没有的事实——只是把「会崩」「每分钟」「催了两次」这些本来就有的细节写出来，并且长短不齐、一句话就写一句。

更多场景（小改动多的一周 / 推进不动的一周 / 没做出东西的一周 / 科研与学生 / 带人 / 同一批材料换顺序）见 `references/examples.md`。

## 九、分工与范围

- **`humanizer-zh`**：通用去 AI 味（31 类模式、保留确定程度、不虚构）。周报草稿写完用户还嫌「AI 味重」就走它，本技能不重复它的规则。
- **`doc-plain-zh`**：把拗口的正式文档改通顺。周报不拗口就不需要。
- **范围**：周报 / 日报 / 月报这类周期性汇报。述职报告、项目复盘要的是叙事与归因，不是条目归位，不在本技能范围内。
