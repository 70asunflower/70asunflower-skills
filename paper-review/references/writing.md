# 写作与改写：从论文故事到对抗性自审

本文件是 `SKILL.md` 中「写作与改写」那一路的细则（原「学术论文写作专家」与「科研论文写作专家」
两个角色的可复用部分合并而来）。审查与写作共用同一套判据，区别只在用法：**审查**是拿判据找缺陷，
**写作**是拿判据生成内容。两条硬约束对两者都成立——**论断-证据对齐**、**引用必须真实可核**。

## 1. 动笔前先把论文故事讲清楚

| 要回答的问题 | 通常落在哪 |
|---|---|
| 解决什么任务？目标指标是什么？ | Abstract 前两句、Intro 第一段 |
| 先验方法为何达不到目标？失败的**技术原因**是什么？ | Intro 第二段——这是论文存在的理由 |
| 核心技术挑战是什么（含物理/工程约束）？ | Intro 第三段 |
| 方案**本质上**怎么工作（一句话机理）？ | 贡献点、Method 首段 |
| 额外贡献（数据集/工具/新发现/负面结果）？ | 贡献列表末条 |

贡献类型决定叙事主线：**新任务 / 新指标 / 新技术挑战 / 新方法 / 新发现**——选一条，全篇不换。
故事没定清就动笔，写出来的段落会各自为政，改起来比重写更贵。

## 2. 先出迷你大纲（3–7 条）再展开

每条 = 一个论点 + 支撑它的证据（图表/数字/引用）。骨架定下来才展开成段。
**反例（禁止）**：先写"朴素方案"再写"我们的改进"——读者会把工作读成低分增量修补。
正确做法是**先让挑战出现，方案作为对挑战的回应**。

## 3. 章节模板

**Abstract**（三选一）：挑战→贡献／挑战→洞见→贡献／多贡献并列（每条一句）。
硬约束：不含公式与引用；数字用实测值并带限定词；末句给影响，不重复贡献列表。

**Introduction**：任务与应用 → 已有做法的局限（附证据）→ 挑战与方案 → 贡献列表（可验证、不夸大）。

**Related Work（必须是脉络，不是清单）**：按流派或技术路线分 2–4 组，每组写
「这一派解决了什么 → 共同局限 → 与本文的关系」，末尾一句点明空白。
**禁止**流水账式"X 做了 A[1]。Y 做了 B[2]。"。

**Method（每个模块三要素）**：动机（为什么需要）→ 设计（怎么做，符号与假设写全）→
技术优势（相对什么、代价是什么）。自检：**删掉这个模块，结论会怎样？答不出说明动机没写清。**

**Experiments**：设定（数据/平台/参数）→ 主结果 → 消融 → 失效情形。每个数字标来源，
对照组要公平且足够强。

**Discussion / Limitations**：主动写局限（样本量、可复现性、外推边界），把审稿人最可能问的
两三点先答掉。**Conclusion**：只写已证实的结论 + 影响 + 下一步，不引入新主张。

## 4. 段落与句子

- **一段一信息**，**首句点题**（该段要说什么），其余句子支撑它。
- 句间关系要显式：因果（因此/因为）、对比（但是/相反）、递进（进一步）。
- 名词首次出现即可自解释，不依赖上下文；缩写在该区域首次出现时给全称。
- **段落角色标注法**（改写时用）：给每段标 `开场/挑战/方法/优势/证据/局限`——
  标不出来的段落，要么删，要么拆。

## 5. 逆向提纲（查流畅性最有效的手段）

1. 把每段首句抄成一行，得到"实际大纲"；
2. 与目标大纲逐条比：缺哪条、多哪条、哪条错位；
3. 把段落内部的证据点列在该段主题句下，检查"证据 → 主题句"是否成立；
4. 无法干净映射的段落修订或删除。

写完后自检用它，接手别人稿件时用它快速判断结构问题。

## 6. 论断-证据对齐（硬约束）

把摘要与引言里的**每一项**主要论断抽出来，逐条填表：

| Claim（原文照抄） | Evidence（本文哪个图表/数字/引用） | Status |
|---|---|---|
| … | Fig. 3(b) 实测曲线 | supported |
| … | 只有仿真，无实测 | **needs evidence → 弱化措辞** |
| … | 无 | **needs evidence → 删除** |

- 只有 `supported` 才允许断言语气（is / does / causes）；
- `needs evidence` 一律降级为 `we attribute / consistent with / appears to`；
- **实测与仿真必须分开表述**，仿真结论不得写成实测（这是最常被审稿人抓住的一条）。

## 7. 对抗性自审（五维评分卡）

以"想拒稿的审稿人"身份重读全文，逐维给 `pass / needs revision / needs new experiment`：

| 维度 | 要问的问题 |
|---|---|
| 贡献度 | 给出了什么新知识？解决的是不是真问题？洞见是否非平凡？ |
| 写作清晰度 | 读者能否复现？每个模块动机是否显式？术语是否统一？ |
| 实验强度 | 相对**强**基线的提升是否显著？绝对值是否达标？ |
| 评估完整性 | 消融是否覆盖关键设计？基线是否公平？有没有只报有利指标？ |
| 方法设计合理性 | 设定现实吗？有没有技术缺陷？收益是否大于复杂度？ |

`needs new experiment` 的项**不能靠改文字解决**，要如实告诉作者，不要用措辞掩盖。

## 8. 图表是一等内容

- 先定"这张图要论证什么"，再画；图注写清"看什么、结论是什么"。
- teaser/总览图让人一眼看懂任务与流程；pipeline 图标清模块、数据流、输入输出与关键符号。
- 表格用 booktabs 风格（少横线、无竖线）；**标注指标方向**（↑好还是↓好）；最优/异常值加粗或标注。
- 图内字号不得低于模板要求（IEEEtran 要求 8 pt Times New Roman）；缩图会同步缩字号，先问作者。
- **图内文字是论文正文的一部分**：与正文的术语、数字必须一致（检测方法见 `SKILL.md` Step 5b）。

## 9. 语言与语域

- 正式学术语体：无口语词、无主观臆断、无术语堆砌腔；对同行严谨、对非本方向读者可读。
- 关键数字配限定词（约/超过/至多/系）并随行标来源与可信度（"公开仿真""经多来源交叉验证"）。
- **不夸大**：`first report` / `novel` / `significant` 必须有依据；对既有工作如实引述其贡献。
- 一句一信息，短句优先；四层以上的逗号嵌套必须拆开。
- 不写评价性套话与强行总结（"本质上…""价值在于…""综上所述…"）；正文不用 emoji。
- **同一概念只用同一个名字**——摘要、正文、图注、图内文字四处一起统一。

## 10. 文献：真实、可核、规范

**这是最硬的一条红线**，与审查侧 Step 4 互补：那边查编号与顺序，这边查**真实性**。

1. 只引**同行评审**来源：期刊、会议论文、学术专著、官方标准与技术报告、学位论文。
   不引博客、百科、新闻、个人主页。工程文档（如厂商设计文件、CAD、数据手册）可以引，
   但必须在条目里标明类型。
2. **每条引用都要能核**：优先通过 Crossref REST API（`https://api.crossref.org/works/<doi>` 或
   `?query.bibliographic=...`）结合 IEEE Xplore、ScienceDirect、SpringerLink、MDPI、AIAA、ESA ESCC、
   JEDEC 等官方源逐项核实：全体作者姓名、准确标题、期刊/会议缩写、正式卷期出版年月（已入卷期的不得沿用
   Early Access 旧年份）、起止页码或电子文章号（`Art. no.`）、会议地点与日期、真实 DOI。
3. **核不到就不写**。宁可删掉这句论断，也不许"凑一条看起来像的文献"。
   记不准的文献标 `[待核实]` 交作者裁决，**不得凭印象补全作者名、页码或年份**；伴生文献清单不得留
   `xxxxxxx` 占位符。
4. 格式全篇符合 `IEEEtran.bst` 规范：
   - `.bib` 中填全所有作者姓名，**不手写 `and others`**（交由 `IEEEtran.bst` 对 ≥7 人自动截断 `et al.`）；
   - 期刊名标准缩写写进 `.bib`（BibTeX 原样输出 `journal` 字段），标题专有名词/缩写加 `{}` 保护；
   - 电子文章号写为 `{{Art. no.} XXXXX}`，**不得把文章号当成单页塞进 `pages = {XXXXX}`**（否则会印成 `p. XXXXX`）；
   - `@manual` 不重复填写相同的 `author` 与 `organization`；在线文档用 `url = {https://...}`。
5. 引用紧贴相关陈述句之后；不引"整段"；**不引没读过的文献**。

## 11. 学术诚信（红线）

- 不捏造数据、结果、引用；不把他人结论当作本文发现。
- 实测、仿真、推测三类结论在文字上必须可区分（见 §6）。
- 涉及人类受试、动物实验、双用途技术时，提示伦理审查与合规要求。
- **润色不得改变论断强度**：把 `may` 写成 `does`、把 `consistent with` 写成 `caused` 是造假，
  不是润色。反向同样成立——不要为了稳妥把已证实的结论弱化成无信息量的句子。
