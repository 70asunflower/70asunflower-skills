# 论文审查检查清单

按维度分组。每条给出**判据**（怎么判定违规）与**处理**（怎么改）。凡判据依赖读音、领域事实或作者意图的，
标记为"需人工确认"，不得由脚本自行判定。

---

## A. 术语与缩写

| # | 判据 | 处理 |
|---|---|---|
| A1 | 缩写首次出现处必须给出全称。用 `\b[A-Z]{2,7}s?\b` 扫全文，找"该缩写第一次单独出现的位置"，与"`全称 (缩写)`"的位置比较；裸用在展开之前即违规 | 把 `(缩写)` 移到裸用之前。**定义位置的选择见 A4** |
| A2 | 同一缩写在同一**区域内**只允许展开一次。区域 = **摘要 / 关键词 / 正文**，三者独立。统计每个区域内 `全称 (缩写)` 的次数，同一区域内 >1 即违规 | 保留最合适的一次，其余改写成裸缩写 |
| A3 | 裸缩写不得早于其**所在区域**的展开 | 同 A1/A4 |
| A4 | **摘要与正文是独立单元，允许各展开一次。** 只看摘要的读者看不到正文的定义，反之亦然 | 判据：每个区域各自在"该缩写此后真的会被用到"的那次首现处定义。**推论：正文不得依赖摘要的定义**——若某缩写只在摘要展开、正文首用裸用，正文仍需在自己的首用处补全称。关键词是标签列表，不是散文，免检 |
| A5 | 概念不可混用：语义不同的词即使字面接近也不能互换。如 "commercial satellite constellations"（商业运营的星座，所有权属性）≠ "COTS"（货架产品，采购属性） | 逐处看语义，不看字面。把同类词的全部出现列出来逐条判定，能改的改、语义不同的**明确标注"刻意保留"** |
| A6 | 大小写与单复数一致：`SEEs`（名词短语）与 `single-event`（定语）不可互替；`SEE` / `SEEs` 混用 | 名词短语位置统一用 `SEEs`；定语位置保留 `single-event` |
| A7 | 关键词是独立元数据，与正文缩写策略可以不同 | 单独判断，不要机械套用正文规则 |
| A8 | 表中术语与正文一致：正文写 `Checker`、表头写 `Analysis Tier` 属不一致 | 统一到正文口径 |
| A9 | **全文只出现一次的全大写缩写：删掉比展开更好。** 一次性缩写（如 `tens of GFLOPS`）展开会让句子变重，而它后面再也不会用到 | 换成同义的普通名词或写全（`tens of gigaflops` / `tens of billions of floating-point operations per second`）。先统计出现次数再决定：**≥2 次才值得定义** |

**脚本能查**：A1、A2、A3（`abbr` 检查项）。**必须人工**：A4、A5、A6 的定语/名词判定、A7。

## B. 引用与文献

| # | 判据 | 处理 |
|---|---|---|
| B1 | `\bibitem` 顺序必须等于正文首次 `\cite` 顺序（IEEE 数字引用制） | 重排文献表。脚本逐位比对并按渲染编号报出首个错位 |
| B2 | 新增一条引用时，若它的首次引用位置在已有条目之前，会顶掉后面所有编号 | **优先把新引用放在其首次出现位置的正确次序上**；若代价过大（要重排整表），改用"已有且已在前文引用过"的条目 |
| B3 | 正文里不得出现硬编码的 `[17]` 这类数字引用 | 一律用 `\cite{}`，编号交给 LaTeX |
| B4 | 每条 `\bibitem` 至少被引用一次；每个 `\cite` 键必须有 `\bibitem` | 脚本双向查 |
| B5 | 文献表顺序与"首次引用顺序"一致时，**不要在文献表中间插新条目**——插一个就整体错位 | 插到正确次序位置，或插在末尾并确认其首次引用确实最晚 |
| B6 | 同一主题的多条引用若地址/编号重复，考虑合并为一条笼统条目 | 合并能省正文与文献表两处篇幅，但会改变可核性，需作者定 |
| B7 | 文档编号、标题、年份、卷期页必须与官方文件或 Crossref API 核对，**不得凭印象写** | 用 `https://api.crossref.org/works/<doi>` 或出版商页面逐项核对；`.bib` 与正文题录不一致时以权威源为准 |
| B8 | 存在 `.bib` 文件但正文用 `\bibitem{}\begin{thebibliography}` 时，`.bib` 对编译无影响 | 要么删掉，要么重建为与正文一致的镜像并在文件头写明"derived，编译不读取"；**不要让两份真相源各自漂移** |
| B9 | **`.bib` 作者列表禁止手写 `and others`（`et al.`）** | 填全出版物上的全部作者姓名；`IEEEtran.bst`（`names.max = 6`）会自动对 $\le 6$ 人全列、对 $\ge 7$ 人截断为 `First Author et al.` |
| B10 | **电子文章号（Article Number）不得裸填进 `pages = {103316}`** | 无 `--` 的单数字会被 `IEEEtran.bst` 误渲染为单页 `p. 103316`；纯文章号期刊用 `{{Art. no.} 103316}`，兼具页码与文章号的 IEEE 期刊写 `pages = {1--14}` + `note = {{Art. no.} 5517414}`（加花括号防 `Art.` 被转小写 `art.`） |
| B11 | **`@manual` 条目禁止同时把同一机构填进 `author` 与 `organization`** | `IEEEtran.bst` 对 `@manual` 会先后输出这两个字段，导致同一机构名（如 ESA、JEDEC）在单条文献中重复打印两次 |
| B12 | **在线手册/标准网址应使用 `url = {https://...}` 而非塞进 `note`** | `IEEEtran.bst` 会自动将 `url` 渲染为模板规定的 `. [Online]. Available: https://...` |
| B13 | **Early Access 年份与正式卷期年份区分** | 论文一旦编入正式卷期（具备 `volume` 与正式页码/文章号），`year` 与 `month` 必须更新为正式卷期出版年月，不得停留在 Early Access 年份 |
| B14 | **伴生文献核查清单（如 `docs/文献引用对照清单.md`）必须与 `.bib` 同步** | 清查伴生文档中残留的 `xxxxxxx` 占位 DOI、错位 DOI 或旧页码（如 `pp. 1--7` vs `pp. 1--6`） |

**脚本能查**：B1、B3、B4、B8–B11（给 `--bib` 时）。**必须人工/API**：B2、B5、B6、B7、B12–B14。

## C. 图表

| # | 判据 | 处理 |
|---|---|---|
| C1 | 图的渲染编号 = 浮动体在源文件中的声明顺序（`\caption` 的执行顺序），与最终落在哪一页无关 | 每次增删图后重新枚举 |
| C2 | 正文首次引用的图必须是 Fig. 1；整体引用序列必须单调不减 | 脚本按渲染编号换算出正文引用序列并检查 |
| C3 | 每个浮动体都要在正文里被引用（IEEE 惯例） | 补引用句，或删掉该图 |
| C4 | 文件名的编号与渲染编号**常常不一致**（历史遗留），不得凭文件名推断图号 | 动手前用脚本取真值；作者口中的"图 N"按渲染编号理解 |
| C5 | 多面板图（a）(b)(c) 每个面板都要在正文交代 | 逐面板检查 |
| C6 | 新增一张图到浮动体序列最前面，会同时破坏 C1 与 C2 | 新增图后必须重跑 C1/C2 检查 |
| C7 | 表格同理：`table` 与 `table*` 都要纳入 |
| C8 | 图注里引用官方资料时，`\cite` 位置与正文一致 | 逐条核对 |
| C9 | **多面板图的图注必须标注 `(a)(b)(c)`，且顺序与图内自带的面板标题一致。** 图内画了 `(a) Rear Face` 而图注只说"两面"，读者无法对应 | 逐条图注检查；单面板图与表格不需要 |
| C10 | 正文若分别论述各面板，引用应到面板级（`Fig.~\ref{f}(a)`），不要整图引用 | 全稿粒度一致 |
| C11 | **`\label` 名必须等于渲染编号**。名字与编号错位时渲染仍正确，但下次挪图 `\ref` 会静默指错 | 逐项比对脚本打印的 `order (rendered number)`；改名是循环置换，必须**一遍映射**完成 |
| C12 | 并排两块面板：宽高比不同时**等宽必然不等高**。等高要把宽度按宽高比反解（见 `latex-ieee.md` §9.3） | 算出两块印出高度；差超过约 10% 就该改。等高的宽度分数与基准宽度无关 |

**脚本能查**：C1、C2、C3、C7。**必须人工**：C5 的叙述质量、C8、C9、C10。

## D. 句子级语法与逻辑

| # | 判据 | 处理 |
|---|---|---|
| D1 | **假主语**：主语与谓语语义不搭。典型——把"动作/流程"当主语去描述其"属性"。例：`onboard deployment of X is compute-intensive and requires high memory bandwidth`——"部署"这个动作既不耗算力也不耗带宽，真正耗的是 X | 把主语换成真正的实体（负载、器件、模型） |
| D2 | **对比两侧不同类**：`In contrast` 前后一端是"硬件能力"、另一端是"行为/流程" | 让两端同属一个范畴（能力 ↔ 能力，需求 ↔ 需求） |
| D3 | **悬空的因果**：`leaving …` / `thereby …` / 分词状语的逻辑主语应能落到前一句的主体上 | 若落不到，补主语或拆句 |
| D4 | **抽象名词当实体的代称**：`the assembly`（谁的装配？）、`the system`（哪一层？） | 换成已定义的实体名（`the DUT`、`the module`） |
| D5 | **术语层级冲突**：论文若把 `system-level` 作为核心术语，就不能同时用 `systems` 指被测对象 | 被测对象统一用 `module` / `device` / `DUT` |
| D6 | 同一段落内相邻两句重复同一个词（如都以 `these modules` 结尾） | 换同义词或改用代词 |
| D7 | 段首句被删后，整段失去主语 | 删句后重读整段 |
| D8 | 一句话里两个近义表达叠用（如 `terminal shutdown` 与 `shut down` 相邻） | 删一个 |
| D9 | 时态、语态在描述同一事件时保持一致 | 全段统一 |
| D10 | 并列项必须同类同形（都是名词短语，或都是从句） | 重写不平行项 |

**全部需人工**。脚本无法判定语义，但可以输出"同一词在相邻句重复""同一段落长度异常"之类的提示。

## E. 数字、单位与冠词

| # | 判据 | 处理 |
|---|---|---|
| E1 | 数字与单位之间用不换行空格 `~`，不得用普通空格 | `48~MeV`、`1.6~mm` |
| E2 | **冠词看读音，不看字母**。`a 48 MeV`（forty-eight，/f/）、`a 14-core`（fourteen）、`a 1.6 mm`（one，/w/）；`an 8 MeV`（eight，/eɪ/）、`an 11 MeV`（eleven）、`an 18 MeV`、`an 80 MeV` | 逐个按读法判定 |
| E3 | 数值范围用 `--`（en dash），不用 `-` | `1--3 years` |
| E4 | 数量级、单位符号全稿统一（`p/cm^2` 与 `p cm^{-2}` 不混用） | 统一 |
| E5 | 同一量的写法一致：正文写 `66.8~W`，摘要不得写 `66.8 W`（缺空格） | 统一 |
| E6 | 四舍五入与有效数字在全稿一致；同一数字在不同位置的位数一致（`9.6 mm` 与 `11.5 mm` 并存即不一致） | 统一口径 |
| E7 | 数值与其限定词共现：`about` / `approximately` / `> ` 与数字匹配，不要漏也不要堆 | 逐处核对 |
| E8 | 速率/百分比等复合写法统一：`0.3\% deviation` 与 `0.32\%` 是否指同一量 | 核对 |

**脚本能查**：E1、E2（`article` 检查项，给出需人工确认清单）。**必须人工**：E3–E8。

## F. LaTeX 静态健康

| # | 判据 | 处理 |
|---|---|---|
| F1 | 源文件应为纯 ASCII（正文英文）。中文注释会引入非 ASCII | 注释改英文；`\cite{}` 之后的说明也用 ASCII |
| F2 | 花括号收支平衡 | 脚本查 |
| F3 | `$` 计数为偶数（含 `$$` 计 2） | 脚本查 |
| F4 | `\begin{}` / `\end{}` 逐环境配对 | 脚本查 |
| F5 | **`\text{}` 是文本模式，不能放数学专有命令**。`\text{ keV/\mu m}` 会导致 `Missing $ inserted`，并级联报后续多处错误与 `Reference undefined` | 拆成 `\text{ keV/}\mu\text{m}`；全文扫描数学专有命令是否误入 `\text{}` |
| F6 | `\includegraphics` 引用的文件必须存在 | 脚本查 |
| F7 | 全角标点不得混入 | 脚本查 |
| F8 | 一次编译报多处错时，**先看第一个错**；后面的往往是级联 | 修第一个再重编 |
| F9 | `\ref` 未定义会造成"图不显示 + 引用变 `??`"，多由前一个语法错误引起 | 先排语法错 |
| F10 | **批量替换 `&` 必须区分转义与裸用**：`\&` 是文本里的字面 &，**裸 `&` 是表格列分隔符** | 替换前按"是否带反斜杠"分成两类，**只改 `\&`**；误改裸 `&` 会让表格结构崩坏（改后跑 `env:tabular` 与题注检查兜底） |

**脚本能查**：F1–F4、F6、F7。**必须人工**：F5 的语义判定（脚本能列出候选）、F8、F9。

## G. 版面与模板合规

| # | 判据 | 处理 |
|---|---|---|
| G1 | 会议模板条款通常要求**未修改**的模板：禁止用额外命令覆盖行距、字号、页边距 | **压页数优先删内容或缩图，不动模板**。改行距/字号属高风险，可能直接拒稿 |
| G2 | `\topfraction` / `\textfraction` / `\floatpagefraction` 若被改过，属偏离模板默认 | 只有为通栏大图才需要；通栏图为 0 时应回落到默认（0.7 / 0.2） |
| G3 | `figure*`（通栏）浮动体只能排页顶，放不下就整页留白，编译日志报 `Underfull \vbox (badness 10000)` | 尽可能把通栏图改单栏；改完留白往往比面积差本身收益更大 |
| G4 | 页数估算：1 栏英寸 = 栏宽 × 1 in；正文行高约 11.5 pt；参考文献行高约 9 pt。A4/Letter 双栏约每页 18.5 栏英寸可用 | 用作**方向性判断**，不作硬结论 |
| G5 | **线性折算偏保守**：实际编译对少量增行有吸收能力（末页余量、浮动体排布松紧） | 不要仅凭"栏英寸不够"就主张删内容，**必须先真实编译** |
| G6 | 图片放置高度 = 栏宽 × 宽度系数 ÷ 图片宽高比 | 缩宽度即等比缩高度；改 `figsize` 而绘图用归一化坐标时**只压扁图形不缩字号** |
| G7 | 浮动体位置说明符：`[!t]` 只许页顶，`[!tb]` 允许栏底，`[!b]` 只许栏底 | 页顶够不上就整块留白时，放宽到 `[!tb]` |
| G8 | 缩图的代价是图内字号同步缩小 | 缩到印出字号低于约 5 pt 前先问作者；交付前把缩图比例记入日志 |
| G9 | **通栏浮动体按两栏计费**：占用 = 2 x 图高，单栏只占 1 x 图高 | 判断"该不该通栏"时把两套成本写成算术比一比，别凭直觉（`latex-ieee.md` §9.1） |
| G10 | **"通栏 + 缩小"凑页数通常是净亏**：缩到够省时，面板可能已小于单栏方案能给的尺寸 | 先解出需要的 s，再看那个 s 下面板宽多少；小于单栏方案即放弃通栏 |
| G11 | **栏内出现"源码里不存在"的空白**（源码该处只有空行）一定是浮动体造成的 | 先量该文档全部标题前间距得到 normal 区间；异常值确认后**临时注释掉通栏浮动体重编译**验证 |
| G12 | **面板印出字号 = 设计字号 x 放置宽度 / 自然宽度** | 逐面板算一遍；低于约 5 pt 就要处理，正解是**按印出宽度重导**（不占版面），不是继续缩 |
| G13 | 页数结论必须来自**真实编译产物**，并要求作者提供 PDF | 拿到 PDF 后先做版本一致性核对（找一个只有最新版才有的字符串），再量页底余量 |

**全部需人工判定**，脚本不查。

## H. 工程流程（怎么改、怎么汇报）

| # | 判据 | 处理 |
|---|---|---|
| H1 | 每次改动前先看 `git status`，确认没有夹带别人的未提交改动 | 报告现状再动手 |
| H2 | 一次只做一个逻辑改动，独立提交 | 便于回滚与定位 |
| H3 | 提交信息写清"改了什么 + 为什么"，不用"update"之类空话 | 前缀用 `fix:` / `docs:` / `polish:` 等 |
| H4 | 每处修改都在同名 `.log.md` 追加一条（改前原文 / 改后原文 / 原因 / 复核数据 / 范围） | 修订历史外置，正文不放修订表 |
| H5 | 修改后立刻跑静态自检 | 见 `scripts/check_paper.py` |
| H6 | 改动超出用户明确指令范围时**先问**；但用户给出的规则若明确适用于别处，可一并应用并**显式报告** | 报告里写清"我多改了什么"，给一句话回退方案 |
| H7 | 只报"已改"不够，要给出**改前→改后**对照表 | 便于作者逐条确认 |
| H8 | 涉及数字的口径（项目数、样本数、四组/五项）全稿一致性必须独立复核 | 发现不一致立即报告 |
| H9 | **正式 `.md` 只用直写方式改**（脚本写盘 / `cat >> file << 'EOF'`）。会做格式规范化的编辑器会把 `~` 变成 `~~`、吃掉 `\_`、重排表格 | 改完核对三件事：`~~` 计数为 0、`\_` 数量与改前一致、`git diff --numstat` 的增删行数与实际改动对得上 |
| H10 | 结构性破坏（如整块移动、批量改名、整个文件重写）用**脚本 + 断言**，不用手工编辑 | 每个替换前 `assert text.count(old) == 1`；不成立就停下报告 |
| H11 | 移动/重命名任何**带 `\cite` 的块**后，必须重跑 `bib-order` | 手写 `\bibitem` 的编号由 bibitem 顺序锁死，位置一变就可能出现"编号倒序" |

## I. 投稿元数据与合规（常被漏、且后果最重）

静态检查查不到这一节，但它决定"能不能投"。

| # | 判据 | 处理 |
|---|---|---|
| I1 | **评审模式（是否双盲/匿名）必须核实**。投稿系统表单里的 "Authors (anonymous)"、"Submission is anonymous…" 本身就是一条证据 | 官网 CFP 打不开时用 Wayback CDX 取证（`cases.md` 第 23 条）；要**两条独立证据**同向才下结论，并标明来源与时效 |
| I2 | 若为双盲：提交稿不得含**作者姓名、单位、通讯邮箱**，**基金致谢也要删**（它同样暴露单位）；PDF 元数据 Author 字段也要清 | 先扫正文有无 `our previous / our group / 单位名 / 项目缩写` 等自引线索；正文干净则匿名版只是三处删除 |
| I3 | 页数上限要以**会议自己的 CFP** 为准，并注意"接收后的正式版可再加 N 页"这类条款 | 不要用别的会议的惯例 |
| I4 | 作者姓名 byline 用**混合大小写**；`SURNAME, INITIALS` 是 Xplore 的**渲染**格式，不是投稿写法 | 与 ORCID 记录保持一致；改 ORCID 名字不会断已有链接（关联基于 iD） |
| I5 | 基金清单应做**全历史比对**（拉出所有历史版本的 `\thanks`），确认当前版是不是并集；同句内编号写法要统一 | 资助归属只有课题组能定，把清单与变更时间线摆出来请作者裁定（`cases.md` 第 22 条） |
| I6 | 截稿时间换算到作者本地时区，并确认"必须点 ready for review 才被评审"之类的硬性动作 | 把换算结果与硬性动作明确写进交付说明 |

**全部需人工 + 外部信息**，脚本不查。

## J. 交付件与产物（投稿前最后一遍）

静态检查只看源文件，查不到"交付件是否等于源"。这一节在投稿前跑一遍。

| # | 判据 | 处理 |
|---|---|---|
| J1 | 交付 PDF / 包的 mtime 必须**晚于所有输入**：`main.tex`、`references.bib`、`cls`、`figures/` 下每一个文件 | 任一输入更新即判过期；列出 mtime 对照 |
| J2 | 最硬的证据：用当前源**重编一遍**，提取文本与交付件**逐字一致** | 比对前先归一化：去空白 **+ 去行末连字符**，否则 `mea-\nsured` 这类断词造成假阴性 |
| J3 | 包内**每个条目**与工作区逐文件哈希一致（不要只比 `main.tex`） | "图件换过而包没重打"是最常见的漏网 |
| J4 | 交付包不含编译产物：`aux`/`log`/`out`/`toc`/`pdf`/`missfont.log`，**以及 `bbl`/`blg`** | 过期 `.bbl` 会静默覆盖 `references.bib`；同时查 `.gitignore` 是否漏了 `.bbl`/`.blg` |
| J5 | 交付 PDF 每种字体都带**子集前缀**（`ABCDEF+`）；PDF 版本在会议接受范围内 | 无前缀的字体可能被会议的 PDF 检查器拒收 |
| J6 | 摘要/关键词的**元数据副本**（投稿表单、README、清单）与 `main.tex` 逐字一致，词数同步 | 摘要一改就必须重跑同步脚本；这类副本漏更新已发生两次 |
| J7 | 仓库里是否有多条工作线在动 | 提交前看 `git status`，按显式 pathspec 暂存；绝不把别人的图件卷进自己的提交 |
| J8 | 由 `.bib` 驱动的稿子，编译是否跑了**四步**（`pdflatex → bibtex → pdflatex → pdflatex`） | 只跑 pdflatex 会沿用旧 `.bbl`；比对 `main.bbl` 与 `references.bib` 的 mtime 即可判定 |

## K. 论断的落点与强度

一条论断很少只出现在一处。这一节防"改了一半"和"说过头"。

| # | 判据 | 处理 |
|---|---|---|
| K1 | 一条论断的**全部落点**是否同步：摘要、贡献列表、正文小节、两条图注、**图内文字**、结论（通常 ≥6 处） | 改一条论断前先枚举全部落点、一次改完；受限于"图改不动"的，标为**未闭合项**并告知作者 |
| K2 | 正文与**图内文字**的术语、数字是否一致（提取图 PDF 的文本层比对） | 术语分裂、"只存在于图里的数字"各单列一类：**需重出图**，不是改措辞 |
| K3 | 同一论断在不同位置的**表述强度**是否一致（`we attribute` / `consistent with` vs `Converged Root Cause`） | 审稿人会引用更强的那处；统一到与证据相称的强度 |
| K4 | 每条因果论断的机理是否**覆盖了观察到的失败类别**，还是只覆盖一半 | 问"这个机理能否解释失败的那条通路"；补齐后处置建议才在正文内立得住 |
| K5 | 摘要里作为**缩写定义处**的那句，其限定词是否与正文一致 | 定义句带限定词时，改正文必须先改定义，否则该限定词会随缩写扩散到全文 |
