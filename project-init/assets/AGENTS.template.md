## 0. 底线（不因项目类型豁免）

1. **git 管理**：项目必须是一个 git 仓库。正式产出必须入库；被忽略的目录不得用 `git add -f` 强行提交；收工前不留未提交的正式文件。
2. **项目记忆与日志**：`memory/MEMORY.md` 记长期记忆，`memory/<YYYY-MM-DD>.md` 记当日工作，逐条追加、不删改旧条目。**每条日志必须写明 `模型：`**——当前 agent 的模型官方名（如 `DeepSeek-V4.1-Flash`、`Claude Sonnet 4.5`），不确定就写 `未知`，不许编造。
3. **就地迭代**：改原文件，禁止 `_v2`、`_final`、`_备份`、`副本`、`(1)` 之类的版本副本。历史交给 git。
4. **正式产出无 AI 痕迹**：见第 4 节。
5. **不擅自改结构**：目录与根文件的职责以第 1 节表格为准，新增目录先登记职责再建。

## 2. 修改与命名

1. 重命名与移动用 `git mv`，并在当日日志记去向；禁止静默删除或改名正式文件。
2. 动手前先看 `git status`；已有无关未提交改动时先向用户说明，别混进本次提交。
3. **命名**：见名知义，禁占位名（新建、未命名、untitled、aaa、123、doc1）；只用中文、字母、数字、连字符、下划线；不含空格与 `# % & { } < > * ? : " | ~ ! @ ^ + =` 等特殊字符；正式文件名不带日期与版本号（时效交给 git 与日志，版本交给台账或 `releases/` 快照）。
4. 文档用中文名；代码遵循所用语言的社区惯例，并全项目统一。

## 3. 记忆与日志

- **`memory/MEMORY.md`**：项目是什么、关键决策、约定与踩过的坑。只留仍然有效的内容，过时条目直接删（历史在 git），不写流水账。
- **`memory/<YYYY-MM-DD>.md`**：当日工作日志，append-only。写入时机：新建或修改正式文件、做出方案选择、发现坑、会话结束。
- 条目格式：

```
## 2026-11-01 18:20 — 一句话摘要
- 模型：DeepSeek-V4.1-Flash
- 摘要：改了什么
- 原因：为什么改
```

## 4. 正式产出无 AI 痕迹

交付内容与代码注释中禁止：

1. **对话腔**："作为一个AI""希望对您有帮助""如果您需要我可以继续""让我们来看""祝您使用愉快"等；
2. **AI 声明与水印**：任何"由 AI 生成/起草/润色"的标注；
3. **emoji 与装饰符号**：正文（含标题、表格、图注）与代码注释不得使用 emoji；
4. **正文内修订记录**：不得出现"修订历史 / 更新记录 / Changelog / 版本记录"章节，修订信息写进日志；
5. **占位残留**："lorem ipsum""此处省略""待补充完整"等（正式 TODO 除外，交付前应清零）。

文风基准：书面、信息密度优先；结论先行，依据随后；枚举用表格或列表，不堆空话。

## 6. git 约定

1. 完成一段工作即提交，message 用语义化前缀：`feat:` / `fix:` / `docs:` / `refactor:` / `chore:`。
2. 提交时用 `git -c user.name="<你的模型官方名>"` **临时**署名，不要写进仓库配置——否则下一个 agent 会顶着你的名字提交。邮箱保持用户自己的。
3. 收工自检：`git status` 中没有未跟踪的正式文件。

## 7. Agent 会话工作流

1. **进入项目**：读本文件 → `memory/MEMORY.md` → 最近一份 `memory/<日期>.md` → `git log --oneline -10`。有 `docs/开发进度.md` 时从「当前功能」行接续。
2. **按需建自己的入口**：项目里没有你所用工具的入口文件时，照下表建一个只指向本文件的薄入口，提交后继续。**只建你自己用的那一个，不代建其他 agent 的**；入口文件不写规范内容。
3. **工作**：按第 1–5 节存放、修改、记日志；临时产物随手进临时区。
4. **收工**：提交 → 追加当日日志 → 汇报（改了哪些文件、当前状态、遗留问题）。
