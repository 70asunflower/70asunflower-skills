## 0. 底线（不因项目类型豁免）

1. **git 管理**：项目必须是一个 git 仓库。正式产出必须入库；被忽略的目录不得用 `git add -f` 强行提交；收工前不留未提交的正式文件。
2. **留痕**：三层都要有——`memory/MEMORY.md`（项目长期记忆）、`memory/<YYYY-MM-DD>.md`（项目日日志）、**每个正式文件配同名 `<主名>.log.md`**（逐文件日志）。逐条追加、不删改旧条目，**每条必须写明 `模型：`**。详见第 3 节。
3. **就地迭代**：改原文件，禁止 `_v2`、`_final`、`_备份`、`副本`、`(1)` 之类的版本副本。历史交给 git。
4. **正式产出无 AI 痕迹**：见第 4 节。
5. **不擅自改结构**：目录与根文件的职责以第 1 节表格为准，新增目录先登记职责再建。

## 2. 修改与命名

1. 重命名与移动用 `git mv`，并在日志中记去向；禁止静默删除或改名正式文件。
2. 动手前先看 `git status`；已有无关未提交改动时先向用户说明，别混进本次提交。
3. **命名（强制，巡检按错误级拦截）**：
   - **见名知义**：名称直接表达内容与用途。禁止「新建文档」「未命名」「untitled」「aaa」「123」「doc1」等占位名。
   - **字符集**：只用中文、字母、数字、连字符（-）、下划线（_）与扩展名点号。禁止空格及 `# % & { } < > * ? : " | ~ ! @ ^ + =` 等特殊字符——跨平台与命令行转义都会出问题。
   - **禁副本式命名**：不得出现 `报告(1).md`、`数据 - 副本.csv` 这类重复副本；需要两份就说明是两份什么。
   - **不带版本号**：不得出现 `_v2`、`_final`、`_定稿` 等，版本交给 git 与台账。
   - **不带日期**（建议级）：正式文件名不含 `20260928`、`2026-09-28` 这类日期——时效由 git 与日志承担。数据文件的日期若属内容本身，须在日志中说明理由。
4. 文档用中文名；代码遵循所用语言的社区惯例，并全项目统一（如 Python 模块 `snake_case`、测试 `test_*.py`）。

## 3. 留痕：三层各管一段

| 层 | 文件 | 记什么 |
|----|------|--------|
| 项目记忆 | `memory/MEMORY.md` | 项目是什么、关键决策、约定与坑。只留仍有效的内容，过时条目直接删（历史在 git）。 |
| 项目日日志 | `memory/<YYYY-MM-DD>.md` | 整个项目当天做了什么、为什么这么定、踩了什么坑。会话级信息写这里。 |
| 逐文件日志 | `<主名>.log.md` | 单个正式文件的每次实质修改。与文件同目录，一文件一份。 |

### 3.1 逐文件日志（每个正式文件必须有）

结构表中标「入库」的目录（`docs/`、`code/` 等）里的**每个正式文件**都必须配一份同名日志，逐条向下追加、不删改旧记录。

- 命名：`<主名>.log.md`。`docs/报告.md` → `docs/报告.log.md`；`docs/report.docx` → `docs/report.log.md`；`code/main.py` → `code/main.log.md`。
- **必须记录**：新建正式文件（首条写明用途）；对正式文件的每次实质修改；重命名、移动、删除（记去向与原因）。高频行级小改动可按日合并为一条，细节历史由 git commit 承担。
- **无需日志**：根目录文件（`AGENTS.md`、`README.md`、各 agent 入口）、`.gitignore`、`docs/releases/` 交付快照、`memory/` 下的两份记忆文件。

### 3.2 条目格式（`模型：` 必填）

项目日日志与逐文件日志用同一格式：

```
## 2026-11-01 18:20 — 创建
- 模型：DeepSeek-V4.1-Flash
- 摘要：这份文件是什么 / 这次改了什么
- 原因：为什么改
```

`模型：` 写当前 agent 的模型官方名（`DeepSeek-V4.1-Flash`、`Claude Sonnet 4.5` 等）；不确定写 `未知`，不许编造。**巡检按错误级拦截缺 `模型：` 的条目**——没有它，改动无法追责。

## 4. 正式产出无 AI 痕迹

交付内容与代码注释中禁止：

1. **对话腔**："作为一个AI""希望对您有帮助""如果您需要我可以继续""让我们来看""祝您使用愉快"等；
2. **AI 声明与水印**：任何"由 AI 生成/起草/润色"的标注；
3. **emoji 与装饰符号**：正文（含标题、表格、图注）与代码注释不得使用 emoji；
4. **正文内修订记录**：不得出现"修订历史 / 更新记录 / Changelog / 版本记录"章节，修订信息写进 `.log.md`；
5. **占位残留**："lorem ipsum""此处省略""待补充完整"等（正式 TODO 除外，交付前应清零）。

文风基准：书面、信息密度优先；结论先行，依据随后；枚举用表格或列表，不堆空话。

## 6. git 约定

1. 完成一段工作即提交，message 用语义化前缀：`feat:` / `fix:` / `docs:` / `refactor:` / `chore:`。
2. 提交时用 `git -c user.name="<你的模型官方名>"` **临时**署名，不要写进仓库配置——否则下一个 agent 会顶着你的名字提交。邮箱保持用户自己的。
3. 收工自检：`git status` 中没有未跟踪的正式文件；新建的正式文件都配了 `.log.md`。

## 7. Agent 会话工作流

1. **进入项目**：读本文件 → `memory/MEMORY.md` → `git log --oneline -10`。有 `docs/开发进度.md` 时从「当前功能」行接续。
2. **按需建自己的入口**：项目里没有你所用工具的入口文件时，照下表建一个只指向本文件的薄入口，提交后继续。**只建你自己用的那一个，不代建其他 agent 的**；入口文件不写规范内容。
3. **工作**：按第 1–5 节存放、修改、记日志；临时产物随手进临时区。
4. **收工**：提交 → 追加当日日日志 `memory/<日期>.md`、补齐各文件 `.log.md` → 汇报（改了哪些文件、当前状态、遗留问题）。
