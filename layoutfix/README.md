# layoutfix

示意图的**几何体检**与**人工微调**。给「agent 画图 → 截图 → 再猜 → 再截图」这个循环换个走法。

```bash
PY=python          # 装了 pymupdf 的解释器即可

$PY layoutfix.py check  fig.svg                 # 体检：把「看着不对」变成可断言的清单
$PY layoutfix.py check  fig.svg --strict        # CI 门禁，有错误即退出码 7
$PY layoutfix.py tune   fig.svg                 # 浏览器里拖动，改完立刻存盘 + 记清单
                                                #   顶栏下拉可切换同目录其他 svg
$PY layoutfix.py nudge  fig.svg --id text:4 --dy -4   # 命令行微调（agent 用）
$PY layoutfix.py ops    fig.svg                 # 看已落地的改动清单
$PY layoutfix.py clean  fig.svg                 # 清理清单：剔零位移、合并同元素碎片
$PY layoutfix.py ls     fig.svg                 # 列出可拖元素
```

依赖：Python 3.10+ 与 `pymupdf`。零前端依赖、无构建步骤。

```bash
pip install pymupdf
```

---

## 为什么不是「更好的批注」

在截图上画圈，agent 还得靠视觉推理「这个圈指的是哪个框」——那一步正是不可靠的那一步。
真正缺的是两样东西：

1. **身份**：每个元素得有个名字，人和 agent 才能指同一件事；
2. **数字**：`往左 1.2mm` 是可执行的，`往左一点` 不是。

所以 `check` 输出的是「`t_beam` 与 `a7` 重叠 1.8×0.6mm」，不是一张标红的图；
`tune` 把「拖一下」翻译成毫米位移，不是把图画歪了存回去。

## 能查出什么

| 检查项 | 说明 | 严重度 |
|---|---|---|
| `text_overlap` | 两段文字包围盒相交 | error |
| `text_occluded` | 文字先画、之后被不透明形状盖住（按绘制顺序判定） | error |
| `text_out_of_canvas` | 文字超出画布，被 viewBox 裁掉 | error |
| `arrow_dangling` | 箭头一端接上框、另一端悬空 | warn |
| `label_offcenter` | 居中标签没落在所在框的水平中心 | warn |

`check` 的 JSON 输出里每条违例都带 `region`（违例区域坐标），可以直接喂给
`snap --clip x,y,w,h` 只截那一小块来看——整图截图换成局部裁剪，视觉判断会准得多。

## AI 怎么读清单（nudge.jsonl）

清单是给 AI 重放和理解的，读法有讲究：

1. **从干净图按序重放**：每条 op 数值自含；图层 op 自带 `parent`（父节点路径）+
   `from`/`to`（子序号），不依赖元素编号——按文件顺序逐条应用，最终态就是人在界面里调出来的样子。
2. **text 操作带 `label`**：move/set 的 op 里有当时的内容摘要（前 16 字）。图重新生成导致
   `text:11` 这类编号漂移时，按 label 对回同一行字，这是跨版本重放的锚点。
3. **先跑 `clean` 再读**：`layoutfix.py clean fig.svg` 剔除零位移废 op、合并同元素连续碎片
   （move 累加位移、set/set_text 取最终值），图文件一个字节不动。清单从 25 条噪音变成 10 条意图。

## 两个都写：改文件 + 记清单

拖动落地时同时做两件事：

- **改 SVG 文件本身** —— 人拖完立刻看到效果，不用等 agent；
- **追加 `<图>.nudge.jsonl`** —— 一行一个位移，agent 下次重新生成时照着重放。

```json
{"id": "text:4", "op": "move", "dx": 0.0, "dy": -4.0, "at": "2026-10-31T21:39:16"}
```

只改文件 → agent 一重跑就丢；只写清单 → 人得等一轮才看到。两个都写才闭环。

除了位移，还能改属性（宽/高/字号/对齐），记成 set 操作。宽高**一次记一条**：
拆成两次 `/set` 会变成两条 op，用户按一次撤销只退回一半，比不改还糟。

```json
{"id": "rect:1", "op": "set", "to": {"width": 300, "height": 90},
 "from": {"width": "260", "height": "78"}}
```

文字内容是 `set_text` 操作：`to` 存逻辑文本（`\n` 分行，服务端编成 tspan），
`from` 存**旧元素整段字节**——撤销是把这段字节原样拼回去，行距节奏和空格一个不动。

```json
{"id": "text:4", "op": "set_text", "to": "第一行\n第二行", "from": "<text x=\"12\" …>旧内容</text>"}
```

多选整体移动是 `move_multi` 操作：`moves` 逐元素带位移，撤销按逆序整体还原——
一次手势一条 op，Ctrl+Z 不会只退一个元素。

```json
{"op": "move_multi", "n": 2, "moves": [{"id": "text:1", "dx": 3.2, "dy": 0},
 {"id": "text:2", "dx": 3.2, "dy": 0}]}
```

`from` 存的是**字符串形式的旧值**（含 `null`，表示原来没这个属性、继承自 CSS）。
撤销靠它精确回退；实测两次 set + 两次 undo 后文件与原图字节完全一致。

存盘时**只改被拖的那一个元素**，其余字节一个不动（`diff` 只有一行，字节数不变），
所以 git diff 干净、不会把注释和属性顺序洗掉。

## 设计上踩过的坑

写这个工具的时间大部分花在这几件事上，记下来省得重踩。1–4 条是假阳性（乱报），5–8 条是假阴性（漏报）——后者更危险；9–16 条是样式、字节、界面与编号层的坑。

**1. 只比 bbox 会得到满屏假阳性。**
背景 `rect 1520×820 fill=white` 覆盖整张图，朴素相交判定会把 112 段文字全判成「被覆盖」。
必须用 `get_texttrace()` 的 `seqno` 与 `get_drawings()` 的 `seqno` **交错排序**，
只报告「文字先画、形状后画」的情况。修完误报从 112 降到 0。

**2. `fill=None` 的描边矩形不遮挡文字。**
面板边框、分隔线这类只有 stroke 的形状，`get_drawings()` 里 `fill` 是 `None`。
不排除掉，一张图能刷出 40 条假的「覆盖 100%」。

**3. 白色描边遮罩会让同一段字画两遍。**
`stroke="#ffffff" stroke-width="4" paint-order="stroke"`（防线条穿字的常用手法）在 MuPDF
里是两次文字绘制。不去重的话，重叠检测会把同一段字当成互相压叠——实测一张图刷出 87 条。

**4. 「悬空箭头」的判据是「只接上了一头」。**
两端都挨着框 = 正常连接线；两端都不挨 = 图例/示意箭头，本来就不连东西；
只有一端接上、另一端悬空才是真缺陷。用「离框远」当判据会把图例箭头全报成错误。

**5. 垂直重叠要拿字号当尺子，不能用固定毫米。**
文字包围盒含上下留白，行距偏紧时相邻两行的 bbox 会「假重叠」0.2–0.4mm，肉眼看完全没事。
实测 0.8mm（约字号 25%）是真挤，0.3mm（约字号 9%）是噪声。阈值取 `0.12 × 字号`。

**6. 横向重叠的两段字绝不能并成一行。**
这是最阴的一个：合并逻辑按「横向相邻」拼接，但没区分相邻和重叠。两段字一旦真的叠在一起，
就被并成同一行，随后「同一行不算重叠」的规则把缺陷全部放过——**要检测的东西被自己抑制了**。
判据必须是：`s.x0 < cur.x1 - tol` 视为不同行。

**7. 合并不能用单指针贪心。**
两段字在 x 方向交错时，前面的行一关闭就再也接不回去，一段字会被拆成好几行，
一条缺陷变成五条报告。要维护一组「开着的行」，每个 span 找第一个能接上的。

**8. 行归属要在合并时定，不能事后靠包围盒反查。**
两行重叠时，后者会被错判给前者，同样触发第 6 条的抑制。

顺带一条：`matplotlib` 默认 `svg.fonttype="path"` 会把文字转成路径，
探测拿到 0 个文字 span——**同时人类也没法在 SVG 里改字**。
要机器可探 + 人类可改，必须 `svg.fonttype="none"`（或 `pdf.fonttype=42`）。

**9. CSS 规则压得住呈现属性——改字号「文件变了、画面不动」。**
图里只要有 `<style>` 块用类定义 `font-size`（很常见），元素上写 `font-size="15"`
就是无效的：按 SVG 规范，CSS 声明优先级高于呈现属性。必须写内联
`style="font-size:15px"`（顺带：CSS 里的 font-size 不能裸写数字，必须带单位）。
`edit.STYLE_PROPS` 里的属性一律走内联样式，几何属性（x/y/width/height）才写呈现属性。
撤销时旧值也要按「样式属性读 style、几何属性读呈现属性」分别记录，否则还原不回去。

**10. 读写必须走字节，不能用 `read_text`/`write_text`。**
Windows 上 `write_text` 会把 `\n` 写成 `\r\n`：源文件是 LF 时，一次拖动就把
整份文件的换行全改掉，`git diff` 变成整文件重写，看起来像重写了整个图。
`read_text` 同样会做 universal newlines 转换。一律 `read_bytes().decode()` /
`write_bytes(encode())`。

**11. 属性名正则要用 `(?<![\w:.-])` 而不是 `\b`。**
`\bwidth\s*=` 会命中 `stroke-width="1.5"` 里的 `width`——于是「改宽度」变成
「改描边粗细」：框没变宽、边框变粗，用户以为改好了。删除属性时还要把前面的
空白一起删，否则撤销后字节对不上。

**12. transform 列表是右起生效的，`translate` 必须放最前面。**
写成 `rotate(...) translate(dx,dy)` 会让位移沿着旋转后的轴走——旋转过的标签
往右拖会往上跑。

> 这条是用户当场撞出来的。**我的自测当时没抓到，因为它断言的是「文件里有这个属性」，
> 而不是「算出来的样式变了」。** 断言要打在最终效果上，不是中间产物上。

**13. 图层重排会改变全图编号，界面必须跟着换选中。**
元素编号（`text:4`）是按文档顺序算的。把一个元素挪到别的图层位置，它自己和其他元素的编号全变了。
`set_order` 必须回报 `eid_after`，前端拿它更新选中——否则刷新后还按旧编号找，
**会选中另一个元素，接着改字号就改错了对象**。

**14. 缩放手柄的 mousedown 不能被"拖动/选中"的监听吃掉。**
两个 `mousedown` 监听都挂在画布上，按注册顺序执行。选中逻辑先跑，遇到手柄时
`closest('[data-ffid]')` 返回 null，于是 `select(null)` 把选中清空，
缩放的监听紧接着 `if(!sel) return` 直接返回——**拖角彻底失效，且没有任何报错**。
手柄事件必须显式跳过选中逻辑。

**15. 别在界面上显示没有入口的指标。**
状态栏曾经有个"已定稿 N"，数据取自"被 move 过的元素集合"，而界面上根本没有定稿按钮。
它要么恒为 0，要么等于改动数，**承诺了一个不存在的能力**。这类假指标比缺功能更伤信任：
用户会去找那个不存在的按钮。同理，"dx 0.00"在没拖动时也显示，看着像已经移动过了。

> 第 5–8 条全是 `tune` 的自测抓出来的：合成一次拖拽，然后比对违例数变化。
> 纯看静态图永远发现不了——**假阴性只有在「你制造了一个已知缺陷」时才暴露**。
> 自测入口：`layoutfix tune fig.svg` 后访问 `/selftest`。

**16. 编号是位置序号，图层一动就整体漂移。**
`text:11` 的含义是「文档里第 11 个 `<text>`」。置顶/上移会把元素挪到别处，
**全图编号前后移**，旧编号指向的已经是另一个元素——而 `set_text` 不会报错，
它会安静地把另一行字换成你给的内容。真实事故：修一处坏折行，用漂移后的
`text:11` 把「每路 CAN 配套 STB/EN/ERR 控制信号」整行替换成了这行文字的副本，
提交信息还写着"已按用户原意修回"。

现在的护栏：`nudge --expect 几个字` 对不上就拒绝；`nudge` 回显实际命中的是
哪一行；`/set`、`/set_text` 返回 `found`。但根子上要记住：**动过图层就重新 `ls`**。
界面上没这个坑——`refresh()` 每次都重新取带编号的副本，人看到的编号永远新鲜；
只有拿着旧编号的脚本会中招。

## 已知边界

- 只处理单页。多页 PDF 只看第一页。
- 坐标默认按 CSS 96dpi 折算毫米；要精确物理尺寸用 `--width-mm` 声明成品宽度。
- `arrow_dangling` 只认 `marker-end` 标记的箭头；手绘多边形箭头认不出。
- `label_offcenter` 只查 `text-anchor="middle"` 的文字；一个框里挤多个居中文字时（引脚编号）自动跳过。
- 拖动界面管**版面 + 图内文字编辑 + 折行 + 线段端点 + 多选**：位置、宽高、字号、对齐、图层、双击文字就地编辑、拖文字手柄调折行宽度（实时重排）、线段端点拖动（自动吸附）、**Ctrl/Shift 加选 + 空白拖框选 + 整体移动**（一条 move_multi op，撤销整体回退）。不支持改颜色 / 字体 / 加粗 / 增删元素。
- 同目录其他 svg 在**顶栏下拉**切换（`?file=`），undo/redo 栈按文件隔离；tune 服务可固定端口常驻。
- 端点手柄只给**无 transform 的 line**；polyline 支持整体拖动时的端点吸附但没有手柄；path 的端点结构复杂（可能是曲线），两者都不放手柄。
- 文字多行用 tspan 实现，行距沿用图里已有的 dy 节奏；全新多行按 字号×1.35 兜底。图内编辑器是 HTML 浮层，落盘仍是纯 `<text>/<tspan>`——没有 foreignObject，出浏览器也照常渲染。折行宽度不落盘：第二次拖动会把现有行合并后再折（CJK 直接拼、拉丁补空格）。

## 谁决定什么

这条边界是有意的，不是没做完：

| | 归谁 | 为什么 |
|---|---|---|
| 颜色、字体、加粗、配色 | **agent** | 这是设计决定，要服从整张图的视觉体系；人在界面上调一个颜色，就会和别的图脱节 |
| 位置、宽高、字号、对齐、图层 | **人** | 这是「差多少」的问题，人有眼睛但说不出数字，界面上拖一下比描述给 agent 快得多 |

工具的本质是换能器：人有品味没有数字，agent 有数字没有品味。
把颜色放进界面，等于让没有全局视野的一方去改视觉体系——那正是这个工具想避免的事。

## 目录

本工具是独立技能 `layoutfix`，位于仓库的 `layoutfix/`。paper-figures 等绘图技能画完后调用它做版面校验。

```
layoutfix/
├── layoutfix.py   命令行入口（check / tune / nudge / ops / ls）
├── probe.py       几何体检引擎（MuPDF 底座 + SVG 身份层）
├── edit.py        元素寻址与位移落地（字节级，只改目标元素）
├── tune.py        本地拖动服务（127.0.0.1，用完 Ctrl+C）
├── web/           拖动界面（单文件，零依赖）
├── demo/demo.svg  本地示例图（带真实压字，不入库：拖动会改它，入库只会带来噪音）
├── DESIGN.md      设计文档：架构、模块契约、阈值、测试矩阵、扩展指南
└── README.md      本文件
```

改内部实现前先读 `DESIGN.md`；项目级协作规范见技能根目录 `../AGENTS.md`（若存在）。
